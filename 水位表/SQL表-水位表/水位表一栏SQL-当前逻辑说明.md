# 水位表一栏 SQL 当前逻辑说明

> 更新时间：2026-08-03
>
> 对应 SQL：`水位表一栏SQL - 修改版.sql`

## 一、用途

该 SQL 以当天水位表“合计”行为基础，为每个符合条件的 `ASIN + 国家` 输出库存、销量、在途、预计断货日期、库存状态、备货周期、建议下单日期和负责人整体库销比等信息。

## 二、最终记录范围

基础记录来自 `daily_sales`，必须同时满足：

- `date = CURRENT_DATE`；
- `shop = '合计'`。

随后按 `ASIN + 国家` 关联 `asin` 主数据，最终只保留：

- `maintenance_level` 不是“变体”；
- `status` 属于“新品、普通、重点”。

当前不再要求 `daily_sales.model` 必须存在于 `sale_model`。因此型号为空或型号尚未登记时，只要 ASIN 主数据满足上述条件，整条记录仍可进入结果。

## 三、基础数据和关联表

| 数据表 | 当前用途 |
|---|---|
| `daily_sales` | 提供当天合计行、加权销量、预估销量、待接收数量、售卖天数等基础数据 |
| `delivery_note` | 汇总真实在途数量 |
| `inventory_base` | 汇总当天 FBA 可售库存和待调仓库存，并提供店铺范围 |
| `woot_statistics` | 判断 ASIN 是否需要加入 Woot 店铺项 |
| `shop` | 将店铺简称补充为带店铺类型的展示名称 |
| `v3_cfg_cycle_param` | 提供各站点淡季和旺季最小备货周期 |
| `product_label_cfg` | 提供按国家和型号配置的产品阶段标签 |
| `asin` | 提供销售负责人、状态和维护等级 |
| `users` | 提供销售负责人及主管的等级和上下级关系 |

## 四、在途库存

从 `delivery_note` 中选择与目标 `ASIN + 国家` 一致的记录，并排除“已索赔”记录。

预计到货或入库日期按以下顺序取值：

```text
estimated_arrival_date 非空时取 estimated_arrival_date
否则取 expected_storage_time
```

记录还必须满足以下任一条件：

- 预计日期不早于今天；
- 状态为“待配货”。

每条记录只累计大于零的 `on_the_way`，然后按 `国家 + ASIN` 汇总。最终在途数量最低为零。

## 五、店铺数据

店铺集合由三部分组成：

1. `daily_sales` 中当天的“合计”行；
2. `inventory_base` 中当天存在的店铺；
3. `woot_statistics` 中存在对应 ASIN 时补充的 `woot` 店铺。

排序时“合计”固定排在第一位，其余店铺按销量降序、店铺名升序排列。

当前最终结果只输出 `shop1`，而“合计”始终优先，因此 `shop1` 通常为“合计”。生成的 `shop_display` 当前没有进入最终输出。

## 六、实时库存

从当天的 `inventory_base` 按 `国家 + ASIN` 汇总：

```text
FBA可售库存 = SUM(afn_fulfillable_quantity)

真实库存 = SUM(
    afn_fulfillable_quantity
    + reserved_fc_transfers
)
```

缺失值均按零计算。

## 七、总库存、可售天数和预计断货日

当前总库存口径为：

```text
总库存 = 在途库存
       + 真实库存
       + quantity_receive
       + overseas_warehouse_test_product
       + overseas_warehouse_new_product
```

加权日销量有效且不为零时：

```text
可售天数 = ROUND(总库存 / weighted_sales, 0)

预计断货日 = 当天日期 + 可售天数

月库销比 = ROUND(总库存 / weighted_sales / 30, 2)
```

`weighted_sales` 为零或空值时，可售天数、预计断货日和月库销比均为空，避免除零。

## 八、产品阶段

首先从 `product_label_cfg` 按 `国家 + 型号` 读取标签。同一组合存在多条非空配置时，当前使用 `MAX(label)` 去重。

没有匹配配置时，按 `days_on_sale` 判断：

| 售卖天数 | 产品阶段 |
|---|---|
| 少于 90 天 | 新品期 |
| 90 至 364 天 | 成长期 |
| 365 天及以上 | 成熟期 |
| 空值 | 空值 |

型号为空时无法命中型号配置，但仍可按售卖天数得到产品阶段。

## 九、库存状态

按照月库销比判断：

| 月库销比 | 状态 |
|---|---|
| 小于 3.5 | 短缺 |
| 3.5 至 5 | 正常 |
| 大于等于 5 | 滞销 |
| 无有效加权销量 | 空值 |

## 十、备货周期

先根据预计断货日的月日判断是否处于旺季：

- 06-10 至 07-10；
- 09-10 至 10-10；
- 11-01 至 12-15。

旺季使用 `cycle_days_peak_min`，其他日期使用 `cycle_days_off_min`。

如果站点在 `v3_cfg_cycle_param` 中没有对应配置，备货周期以及依赖该周期的计算结果会为空。

## 十一、建议下单数量

当前 SQL 的实际公式为：

```text
建议下单数量 = ROUND(
    备货周期 × weighted_sales
    - (
        在途库存
        + 真实库存
        + quantity_receive
        + 海外仓新品
        + 海外仓测品
        + quantity_receive
      ),
    0
)
```

当前公式中 `quantity_receive` 被减了两次。本说明只记录现行计算逻辑，不代表该重复减算已经被确认或修正。

当前公式也没有将负数限制为零，因此库存充足时建议下单数量可能为负数。

## 十二、建议下单日期

```text
建议下单日期 = 预计断货日 - 备货周期
```

加权销量无效、预计断货日为空，或站点没有备货周期配置时，建议下单日期为空。

## 十三、负责人和整体库销比

通过 `ASIN + 国家` 关联 `asin.unique`，读取销售负责人；再通过 `users.username` 关联销售用户和主管。

输出内容包括：

- 销售负责人；
- 主管；
- 销售等级；
- 主管等级。

销售负责人整体库销比使用窗口函数计算：

```text
负责人整体库销比 = ROUND(
    该负责人名下全部结果行的总库存
    / 该负责人名下全部结果行的加权销量合计
    / 30,
    2
)
```

## 十四、当前未使用或隐含的逻辑

### 1. `stockout_lookup` 未进入最终计算

SQL 已查找未来 `inventory < 0` 的首次日期，并关联为 `sl`，但最终没有输出或引用该值。

### 2. `asin` 左连接实际具有筛选效果

虽然 `asin` 使用 `LEFT JOIN`，但最终 `WHERE` 依赖 `asin.status` 和 `asin.maintenance_level`。无法匹配 ASIN 主数据的记录不会通过最终条件，实际效果接近内连接。

### 3. 型号不再作为整行显示条件

删除 `sale_model` 内连接后，型号为空不会影响库存和销量等主要计算，但会影响按型号关联的产品标签配置。

## 十五、修改后的验证重点

后续调整该 SQL 时，至少检查：

1. 当天“合计”行的数量是否符合预期；
2. 型号为空或未登记的合格 ASIN 是否仍能显示；
3. 原有可匹配型号记录的库存、销量、在途和备货结果是否保持不变；
4. 加权销量为零或空值时是否仍能避免除零；
5. 没有周期配置的站点是否按预期返回空值；
6. `quantity_receive` 的重复减算是否仍是确认后的业务口径；
7. 是否需要继续保留未使用的 `stockout_lookup` 和店铺展示计算。
