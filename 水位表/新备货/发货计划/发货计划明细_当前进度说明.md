## 一、当前状态

发货计划明细区块已完成，当前实现包含：

- 从 `simulate_shipment` 读取系统发货计划。
- 按当前用户身份限制可见的国家和 ASIN。
- 支持“国家”和“ASIN”多选、搜索及清空筛选。
- 按站点、实际发运日和渠道汇总发货计划。
- 展示计划发货周、波次、发货量、箱数、分票数量及销售日期等信息。
- 渠道名称直接读取 `simulate_shipment.channel`，不从计划快照中取渠道名称。
- 已取消“大号1”和“大号2”列。
- 表头和表格数据均统一居中。
- 已调整表头颜色、行背景、悬停状态和间距，使表格整体保持协调、整洁。
- 未使用 `document`、DOM 查询或HTML注入等能力，页面通过 NocoBase JS Block 上下文中的 React、Ant Design 和 API 渲染。

## 二、数据读取范围

主数据表为 `simulate_shipment`，仅读取同时满足以下条件的记录：

| 条件 | 当前取值 | 作用 |
| --- | --- | --- |
| `plan_source` | `shipment_plan_v2` | 只展示系统生成的发货计划 |
| `shop` | `合计` | 避免重复展示店铺拆分数据 |
| `number` | 大于 `0` | 不展示没有建议发货量的记录 |
| `asin + country` | 当前用户可见商品范围 | 限制用户只能查看有权限的商品 |

读取的 `simulate_shipment` 字段包括：

- `id`
- `asin`
- `country`
- `shop`
- `channel`
- `number`
- `date`
- `add_date`
- `plan_source`
- `v2_calculation_snapshot`

接口结果按 `date,country,channel` 排序。为避免单次商品范围过大，可见商品会按每批12个拆分查询，最后合并结果。

## 三、可见权限规则

页面先从 `asin` 表确定当前用户可见的商品，再据此查询发货计划。

商品必须同时满足：

- 状态为“普通”“新品”或“重点”。
- ASIN和站点均有值。
- `maintenance_level` 不等于“变体”。

不同人员的数据范围如下：

| 人员类型 | 可见范围 |
| --- | --- |
| 系统管理员、管理员或效率部 | 全部符合条件的商品 |
| 销售主管角色 `r_7ih2kbf7t1g` | 自己负责管理的销售人员名下商品 |
| 物流仓储部 | 全部符合条件的商品 |
| 销售部普通成员 | `sale_owner` 等于当前用户名的商品 |
| 其他人员 | 不展示数据 |

## 四、筛选功能

当前提供两个筛选项：

| 筛选项 | 功能 |
| --- | --- |
| 国家 | 多选、搜索、清空；选项显示该国家当前可见计划条数 |
| ASIN | 多选、搜索、清空；选项显示该 ASIN 当前可见计划条数 |

筛选在前端对已读取的可见计划执行。筛选完成后，页面会重新汇总表格，并显示“计划条数”和“发货波次数量”。

## 五、分组和波次规则

表格以以下三个字段作为一个汇总组：

```text
站点 country + 实际发运日 date + 渠道 channel
```

同一组内不同 ASIN 的发货量、箱数和分票信息会合并展示。

波次按每个站点当前结果中的不同实际发运日依次编号：

```text
CA-W01、CA-W02、US-W01……
```

国家或ASIN筛选变化后，波次会根据筛选后的结果重新编号。

## 六、当前展示列

当前表格共展示10列：

| 列名 | 数据来源或计算方式 |
| --- | --- |
| 计划发货周 | 根据 `simulate_shipment.date` 计算该日期所在周的周一至周五 |
| 渠道实际发运日 | `simulate_shipment.date` |
| 波次 | 按站点的实际发运日顺序生成 `站点-W序号` |
| 站点 | `simulate_shipment.country` |
| 渠道 | 直接读取 `simulate_shipment.channel` |
| 发货量 | 汇总组内 `simulate_shipment.number` 的合计值 |
| 箱数 | 汇总 `v2_calculation_snapshot.constraint_layer.boxes`；快照缺失时显示横线 |
| 分票数量 | 使用快照中的 `tickets`、`boxes`、`units_per_box`，按各计划快照的箱入数均衡拆票后汇总展示 |
| 预计可售日 | 汇总组内 `simulate_shipment.add_date`；存在多个日期时显示最早至最晚日期 |
| 覆盖销售日期 | 优先读取快照中的服务期起止日；快照没有服务期时，根据 `add_date + 7天` 至 `add_date + 13天` 展示 |

“大号1”和“大号2”不在当前列中。

## 七、分票展示规则

分票信息读取每条计划快照中的：

- `constraint_layer.boxes`
- `constraint_layer.tickets`
- `constraint_layer.units_per_box`

每条计划先按票数均衡分配箱数，再用“每票箱数 × 箱入数”得到每票数量。表格显示形式如下：

```text
3票：258 + 252 + 252
```

如果相关快照字段不完整，该汇总行的箱数或分票数量显示横线，不自行猜测数据。

- 包含加载中、无数据、筛选无结果和读取失败状态。
